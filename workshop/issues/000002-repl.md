# define REPL: bare invocation reads words, defines and speaks them

## Problem

`define <word>` is one lookup per shell invocation. Looking up five words means
five invocations, and re-hearing a word means retyping it. The pronunciation is
the part most worth repeating, and it is the most awkward to repeat.

## Spec

Bare `define` (no arguments) opens a read-eval loop:

```
$ define
› sycophantic
sycophantic  syc·o·phan·tic
/ˌsikəˈfan(t)ik/
  adjective  behaving or done in an obsequious way…
  ♫ playing 3×
›                      ← bare return: replays the SAME word 3×
› ephemeral
…
› ^C                   ← quits
```

- A word replaces the current one; a bare return replays the current one's
  **pronunciation only** — no definition reprinted (operator, 2026-08-20). The
  repeat count is `-times N`, already customizable.
- Ctrl-C exits cleanly (and must not kill playback mid-file leaving a temp file).
- Not a mode flag: bare invocation is the trigger, so `define` alone is the
  friendly entry point and `define <word>` stays the one-shot path.
- The audio is **cached per word for the session**, so a replay does not re-fetch.
- Reuses `run()`'s existing seams unchanged — this is a loop around the same
  shell, not a second implementation (ARCH-DRY).
- The loop reads stdin unconditionally and prompts only when stdin is a terminal,
  so there is no second code path for batch use.
- **`echo word | define` does not work today** — verified: no-args exits 2 with
  usage. Making it define the word is a *new* capability of this issue, not
  behaviour being preserved. An earlier draft of this Spec claimed otherwise.

## Log

### 2026-08-20

Created as part of the `define-learn` project.

**Done.** Verified through a real pty, which is the only way to test the parts
that matter: prompt appears on a TTY and is reprinted after output, a bare return
replays, a real SIGINT mid-playback exits 0, and zero temp dirs are left behind
on any path (normal, piped, or interrupted).

The plan gate was right about `echo word | define`: I had written that it "still"
works, and it never has — no-args exited 2 with usage. Reading stdin is new
capability here. Correcting that simplified the design: the loop reads stdin
unconditionally and only the prompt is TTY-conditional, so there is no
interactive/batch branch and the whole loop is drivable from a string.

`run` gained `ctx` and `stdin` parameters — the only signature change, both
forced (it previously manufactured `context.Background()` inline, which no test
could cancel). `TestRunNoArgsIsUsageError` was rewritten rather than deleted, so
the no-args branch never went untested while its contract moved.

Timing does not prove the audio cache — playback dominates by two orders of
magnitude — so the proof is `fakeCDN.Requested()` having length 1 across two
definitions.
